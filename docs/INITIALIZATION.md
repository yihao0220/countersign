## 两种启动方式

| 命令 | 部署时的状态 | 初始配置方式 |
|---|---|---|
| `./local.sh start` | 原演示：供应商 7、PO-101、首个 Agent、预算和资金已预置 | 预置项不经过时间锁；第二个 Agent 延迟授权 |

`start-empty` 完成初始化且核对状态后，才启动后端和原页面。页面入口仍为 http://127.0.0.1:5173/#/inbox，布局、样式和原文案不变。两种方式的初始余额均为 500、PO-101 额度 500、每日上限 200；空模式另外登记供应商 8 和周期 PO-102。

同一模式已运行时复用当前实例。另一模式正在运行时拒绝切换，提示先自行执行 `./local.sh stop`；不会自动停止当前链。确认要另建测试实例后，再执行 `./local.sh start-empty`。停止后重新启动是新链、新合约和新账本，**不是升级旧合约或迁移旧状态**；旧运行记录保留在忽略目录 `.runtime/`。

## 从空到可付款的过程

构造函数签名保持五参数：`constructor(address agent_, address payout_, uint256 budget_, uint64 expiry_, uint256 dailyLimit_)`。

五参数全部为零且部署附带资金为零，才选择空模式。Owner 固定为部署者；其他合法预置参数仍走原演示方式，部分零配置沿用原校验。非 31337 链仍拒绝部署。

| 阶段 | 操作 | 生效结果 |
|---|---|---|
| 刚部署 | 五参数为零，部署资金为零 | 登记数、预算、每日上限、余额、Agent 权限均为零；暂停 |
| 第一轮排队 | 两家供应商、guarded / naive 两个 Agent、每日上限 200 | 尚未生效 |
| 第一轮等待及执行 | 模拟推进 120 秒，再逐笔 execute | 供应商及 Agent 已登记，每日上限 200；仍无 PO、仍暂停 |
| 第二轮排队 | 两份 PO、恢复付款；另行充值 500 | 资金已到账；PO 和恢复尚未生效 |
| 第二轮等待及执行 | 模拟推进 120 秒，再逐笔 execute | 两份 PO 可用且恢复付款，检查配置后启动服务 |

供应商登记还未执行时，不能为它排队创建 PO；两轮等待不能合并成一次。达到执行时间不会自动生效。Owner 可取消，重新排队重新等待。这里复用现有管理入口，没有免等待的初始化函数。

| 配置 | 空模式启动值 |
|---|---|
| 供应商 | 7、8，各自独立登记收款地址 |
| Agent | guarded、naive，分别延迟授权 |
| PO-101 | 归属供应商 7，一次性额度 500，到期为配置时刻后 30 天 |
| PO-102 | 归属供应商 8，每 30 天额度 100，到期为配置时刻后 365 天 |
| 全金库每日上限 | 200，UTC 换日，与 PO 周期分别计算 |
| 金库资金 | 500 LOCAL，单独充值 |

两个 PO 的预算合计 600，但金库只有 500。预算是付款许可，不能当成已经存入或预留的资金；付款还要检查实际余额。30 天周期按 PO 执行时刻起算，并非自然月，跨周期恢复一份额度而不会增加余额或清空累计历史。

## 查询字段与兼容规则

- 空模式 `agent()` 始终为零，实际权限必须查 `authorizedAgents(account)`。
- 供应商 7 经执行登记后才设置兼容 `payout()`；PO-101 经执行创建后才设置其 `totalBudget / remainingBudget / poExpiry`，`totalSpent` 随实际付款累加。创建前均为零。`totalPaid` 汇总全部 PO 的付款。
- PO-101 只允许一次性预算，禁止周期配置，保持旧累计口径；周期 PO 可使用其他 ID，例如 102。
- `poExpiry` 从构造时固定字段变为存储字段，以支持延迟创建 PO-101；getter 签名不变，仅创建时设置。PO 编号不能重用，创建后仍无延期入口。调额不能抹掉已付记录。
- 拒付编码 0–13、Paid / Blocked 语义、立即撤销 Agent / 降额 / 停用 / 关闭，以及恢复等待 120 秒均保留。未授权 Agent 调用回滚，不产生规则拒付事件。

完整函数与事件见 [本地接口 v1](CONTRACT_INTERFACE.md)。

## 本地时钟、记录与失败处理

脚本只接受 `http://127.0.0.1` 的本机 Anvil 31337。空模式新 Anvil 的初始时钟回退 240 秒，再模拟推进两轮各 120 秒；预置模式回退 120 秒并推进一轮。初始化完成后按 1 秒出块继续，后续页面申请仍需完整等待新的 120 秒。真实生产链没有这套模拟时间操作。

每笔初始化交易检查成功回执；排队记录检查 changeId 和执行时间，最后检查供应商、PO、权限、余额及暂停状态。`.runtime/<运行编号>/chain.json` 保存公开地址、部署交易/区块、`initialization_mode`、部署空状态和初始化交易轨迹；空模式为 8 次排队、8 次执行、1 次充值。不会保存或输出私钥。

初始化失败则不写 ready、不启动后端和页面，停止本次启动的子进程。不会关闭其他已有服务。排查见 [本地启动说明](LOCAL_TEST.md)。
