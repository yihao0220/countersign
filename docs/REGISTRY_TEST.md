## 操作

打开 http://127.0.0.1:5173/#/controls ，连接“本机测试账户（无真实签名）”。空输入、未连接 Owner、其他操作处理中会禁用按钮。

1. 供应商：填一个未使用的正整数编号和完整收款地址，点“新增供应商”。等待 2 分钟后，到“等待中的变更”点执行，登记表才出现该供应商。可取消；取消后不能执行旧申请。
2. 预算：填新采购单编号、选择启用供应商、额度、到期日和周期天数。排队并执行后出现 PO。0 为一次性，正数按天循环；到期日按北京时间当日 23:59:59。
3. 付款：挑战页文字输入结构化 JSON，例如 `{"invoice_number":"NEW-001","vendor_id":8,"po_id":102,"amount":"10"}`。默认读该供应商登记地址；仍是本地测试规则，没有真实 AI。
4. 关闭：点击目标采购单“关闭”，立即阻止该 PO 后续付款，保留累计账目。不能用相同编号重新新增。
5. 停用：点击目标供应商“停用”，立即阻止其所有 PO 的付款，并取消该供应商待执行改地址。不会影响其他供应商。
6. 提款：填金额，排队等待 2 分钟后执行；只会转到 Owner，不能改收款人。提款减少实际余额，不增加或重置预算。等待中付款可能使余额不足；此时执行失败，仍可取消，或充值后重试。

新增供应商尚在等待时不能为它创建 PO。停用和关闭为永久状态，记录保留，编号不可重用。本轮不提供重新启用或重新打开功能。

## 预算口径

每个 PO 独立额度，所有 PO 共用每日上限、Agent 权限、金库余额和防重记录。所有授权 Agent 对同一账单只能成功付款一次，即使换 PO 也不能重复。

周期以 PO 执行时刻为起点。跨周期恢复一份 cap，不累计旧剩余额度；查询即显示当前周期可用额度，不需要定时任务。关闭或到期后为零；供应商停用保留 PO 账目，但禁止付款。额度是付款许可，不是已预留资金，实际付款还要检查金库余额。

旧 totalBudget/remainingBudget/totalSpent/poExpiry 查询表示 PO-101，totalPaid 表示全部 PO 的累计付款。每日上限按 UTC 日期统计，不随新增 PO、关闭、提款或改地址清空。
