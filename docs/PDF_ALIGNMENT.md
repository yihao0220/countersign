## 已确认的调整与待对齐接口

以下规则经本次会话用户明确确认，保留当前实现；尚无证据表明团队已统一采纳。接入前需要同步，不能称为与 PDF 完全一致。

| 项目 | 原 PDF | 当前行为与影响 |
|---|---|---|
| Agent 权限入口 | queueAgent(address,bool)，一般规则变更等待时间锁 | queueAgentAuthorization 负责延迟授权，revokeAgent 立即撤销；撤销还取消同地址 pending。第 6 页没有给撤销列立即生效例外 |
| 每日上限入口 | queueDailyCap(uint256)，降低立即生效 | queueLimitIncrease / decreaseLimit 以 LimitKind 区分每日和总预算；行为大体对应，但 ABI 名称与参数不同 |
| 采购单预算调整 | queuePO 设置采购单 cap 等字段，没有直接定义当前拆分的调额入口 | 用户确认扩展 decreasePOBudget / queuePOBudgetIncrease 到任意 PO：降额立即生效、提额等待 120 秒，保留账目；一次性不得低于累计已付，周期不得低于本周期已付。降额或关闭取消该 PO 旧提额。旧 TotalBudget 仅针对 PO-101，DailyLimit 针对全金库；第六项已补本地操作白名单和查询，未新增调额表单 |
| 恢复付款 | 有 pause，未列恢复接口或等待规则 | queueResume 等待 120 秒后执行；不能立即恢复 |
| 初始供应商、采购单、Agent 设置 | 通过登记流程设置，新的规则需排队 | 用户确认保留预置演示并增加空模式：空部署后供应商/Agent/每日上限第一轮等待，PO/恢复第二轮等待；预置模式的构造设置仍不能算入时间锁覆盖 |
| 截止时间 | queuePO 输入 expiry | 每个 PO 的 expiry 排队时指定，创建后固定且不可延期；预置 PO-101 由构造函数设置，空模式由延迟创建设置。PO-101 只允许一次性，其他 ID 支持周期，以保持旧查询口径 |
| 等待时间 | 演示 120 秒，真实使用 48 小时 | 当前常量 120 秒且仅本地；生产等待时长需正式配置和验证 |

第六项已固定本地合约名称、函数签名、查询字段、事件和拒付编码，交付见 [本地接口 v1](CONTRACT_INTERFACE.md) 及其中 ABI JSON/共享定义。团队需明确采纳这些实际接口，其余入口不可默认按 PDF 名称直接调用。本轮没有重新核实 PDF 临时附件。

## 用户分工与团队交付的边界

PDF 第 8 页的 Contracts 角色包括：合约、测试、部署、tx writer。前三项不等于整个合约角色完成，交易发送模块也需要有人落实。
当前已导入团队页面并接通本地接口；AI 提取/隐藏文本检测/模型 guard、两个真实模型 Agent、真实钱包签名、现场 bounty 和学习循环尚未接入。
PDF 第 13—15 页还要求说明比赛期间新增与复用内容，以及部署、初始化、付款与拒付的浏览器链接。本地原型和测试不能代替这些交付证据；日程与赛事许可没有在本次重新核验。
PDF 的宣传语不作为安全证明：目前只能说明覆盖的付款规则按预期运行，不能宣称不可被盗，或凭 invoiceHash 判断发票真实。

## 本轮新增及剩余边界

2026-10-07 用户授权的五项控制台功能已完成本地实现。提款为延迟固定向 Owner 提取，金额不计入供应商付款或每日用量；“提款”来自已确认的团队页面接口，本文没有补造未重新核实的 PDF 页码。

当前保留固定 Owner、虚拟原生币和 120 秒时间锁。剩余为 Owner 两步交接/正式组件对齐、ERC-20（若选 USDT）、生产 tx writer 与恢复、正式部署/fork 验证及团队接口统一。按用户要求继续不连接公链、不发布公网；未自动批准这些后续功能。
