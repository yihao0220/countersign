# Countersign 首页、登录与工作台

用户已在本次对话确认实施。

流程：首页 → 登录/注册 → 发票工作台。深链接经登录后回到原页面，退出及失效清除页面缓存。

视觉以 https://os.virtuals.io/ 为基准：白底、深绿色行动按钮、细边框卡片、双栏首屏、终端演示、顶栏与横向二级导航。品牌和正文采用 Countersign，演示明确标注本地虚拟资金。登录页复用附件的字段、校验、错误与等待状态并适配 React；服务复用附件 server.mjs。

现有账本、发票、管理、挑战均放在登录之后。后台也校验 Node 服务签发的 HttpOnly 会话；仅前端拦截不算完成。登录不赋予 Owner 权限，现有钱包及本机账户检查保留。本地版所有账户进入同一个演示工作区，不新增组织隔离或生产角色系统。

保留 Node 认证服务，Vite 同源代理认证和 Python 接口；新启动时配置 Python 会话校验。认证账户存放 .runtime/accounts（忽略 Git），不导入附件现有用户数据，密码仅保存 scrypt 哈希。会话在认证服务重启后失效。

备选方案为迁移认证到 Python，改动较大，本次未采用。不修改 Solidity，不自动重启当前链，不 commit/push，不部署公网。

验收：Node 原认证测试；Python 会话边界测试和已有回归；前端类型、接口、控制台检查与构建；独立 Anvil、后台、认证与浏览器中实际注册/登录/退出/刷新/深链接/无会话拒绝/发票与管理操作；桌面和手机检查无溢出与坏链。运行验证不等同公链、真实钱包签名、生产认证或审计。
