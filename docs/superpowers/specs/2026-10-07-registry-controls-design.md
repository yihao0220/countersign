# 本地供应商、采购单和提款扩展

2026-10-07，用户明确要求补控制台五项缺口并回复“继续”。范围为新增/停用供应商、新增/关闭采购单、延迟提款；沿用原页面，不改布局、样式、文案，运行仍限定 Anvil 31337。

## 数据与规则

供应商通过 queueAddVendor 登记 ID 与 payout，120 秒后 execute 生效；一个 ID 一项待执行申请，重复 ID 不覆盖历史。deactivateVendor 立即停用，并取消该供应商待执行改地址；停用永久保留记录，不允许通过重新登记复活。已有 queuePayoutChange 支持每家供应商独立排队。

采购单通过 queueAddPO 输入 ID、供应商、cap、expiry、periodDays。仅已登记且启用的供应商可申请，执行时再次检查启用状态与截止时间。每个采购单分别记额度、周期支出与累计已付，PO 不可借用另一供应商的预算。closePO 立即永久关闭，编号不能重用。

periodDays=0 为一次性。正数周期从 execute 时刻开始，恰好到新周期时恢复 cap，未用额度不累加；只恢复许可额度，不增加金库资金。关闭、到期、全局防重和每日限额保持有效。

所有 PO 共用金库余额、UTC 每日限额、Agent 权限和 paidInvoices。兼容旧接口的 totalBudget/remainingBudget/totalSpent/poExpiry 只表示初始 PO-101；新 totalPaid 汇总全金库实际供应商付款。提款不计入供应商付款或每日用量。

queueWithdraw 只接受金额，不能指定收款人；固定 immutable Owner 接收。排队时与执行时检查余额，每次仅一项待执行提款。执行前等待 120 秒；任意人可执行到期的确定内容，Owner 可取消。转账失败整体回滚，记录仍待执行；执行成功不可重放。pause 只限制 Agent 付款，管理操作及提款继续可执行。

新增拒付原因追加在原枚举末尾：VendorInactive、POVendorMismatch、POClosed，不改变原 0–10 编号。授权 Agent 的规则拒付仍产生 Blocked，未授权调用仍回滚。

## 对接与验收

后端真实查询 vendors、purchaseOrders、poRemaining，列出新排队记录，使用实际 ABI 调用合约并解析事件。JSON 付款按供应商读取登记地址，金额仍使用十进制字符串与整数最小单位。到期日按现有页面输入解释为北京时间当日 23:59:59。

前端只扩展 lib/localOwner.ts 的操作白名单，现有五个按钮保持原布局与文案，真实请求 /api/local/owner。旧链需重启部署新合约；旧测试数据留在忽略目录。

验收覆盖：等待/取消/重放、权限、编号防覆盖、停用/关闭立即拒付、归属与独立预算、跨 PO 防重、周期边界、提款固定地址/失败回滚/回调重入，以及原有 107 项合约测试。另做 HTTP→数据库→Anvil 的原页面动作测试和浏览器实测。
