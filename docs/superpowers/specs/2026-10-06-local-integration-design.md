# 第一版本地整合

用户已确认：先不上公链。沿用已展示的本机模拟链方案；服务只监听 127.0.0.1，不部署公网、不提交或推送代码。

## 三份代码

- 前端取自 thedarkich/countersign 的 frontend，快照 7a522378aa35769a3a53186d0193ad7714332d01；该仓库还含另一套后端、合约，不替换用户本地合约。
- 后端取自 hyptonize/-hackathon，快照 e2b060ef04e0e9e466168bb79f7cb39e39d9a6bc，保留上传、SQLite 持久化和原有 mock 测试接口。
- 合约使用当前 contracts/src/CountersignDemo.sol，Solidity 0.8.30，仅 chain ID 31337。

## 用户可见流程

页面提交本地测试账单 → 后端验证字段并保存 → 测试 Agent 提出付款 → 后端通过本机 Anvil 测试账户调用 pay → 解码实际 Paid/Blocked 回执 → 页面显示结果、账本和余额。

保留上传、收件箱、控制台、账本四个页面和中文/英文。默认不调用付费模型；测试样例和规则处理明确标注为本地测试，不声称真实 AI 识别或隐藏文本检测完成。无法识别的上传进入待人工核对状态。

只接现有单供应商 7、单采购单 101、共享金库。现有暂停、延迟恢复、地址变更、额度管理和 Agent 权限尽量接入；新增供应商/采购单、周期补额和提款显示不支持。相同账单跨 Agent 共享防重记录，不能为制造两个成功结果而改变 invoiceHash。

## 实现边界

前端增加 local 网络与本地控制入口，停止公共 RPC 和区块浏览器链接。后端增加前端兼容 API、本地交易执行和事件入账。使用 Anvil 自带解锁的无价值测试账户，不保存任何私钥；拒绝非回环 RPC 或非 31337 网络。所有账户只属于本地测试。

启动脚本完成工具检查、合约构建、启动 Anvil、部署和初始化、启动后端及前端；本地运行状态进入忽略目录。停止脚本仅停止本次启动的进程。重启创建新链实例并隔离数据库，避免旧交易记录冒充新链状态。浏览器刷新保留同次运行的数据。

## 验收

运行既有合约、后端测试和前端类型/构建检查。增加跨层测试：正常付款、地址错误、重复账单、超额、暂停、恢复时间锁，核对 receipt 事件、预算和实际余额。浏览器打开四页，完成实际提交和管理操作，检查无页面错误、无公共网络请求。

这些证据只证明本地集成；不证明公链、真实模型、真实钱包签名或安全审计完成。
