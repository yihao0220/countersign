## 已实现规则

- 多供应商、多采购单：每个 PO 归属一家供应商，分别扣预算；共享金库余额、UTC 每日上限、Agent 权限和账单防重记录。
- 新增供应商、PO、提款，以及改收款地址、恢复付款、提额和 Agent 授权等待 120 秒。Owner 可取消；任何人只能执行已批准且到期的确定内容，取消和已执行记录不可重放。
- 停用供应商、关闭 PO、暂停付款、降额和撤销 Agent 立即生效。供应商停用与 PO 关闭为永久状态，登记编号不能覆盖或重用。
- 每个 PO 的截止时间固定；到期不付、不扣账。periodDays=0 为一次性，正数按执行时刻起算周期，跨周期恢复一份 cap，旧余额不累加，也不给金库充值。
- 提款固定转给 Owner，执行时重新查余额；失败整体回滚，可取消或充值后重试。提款不消耗每日用量，不计入供应商付款。pause 只阻止 Agent 付款。
- totalBudget/remainingBudget/totalSpent/poExpiry 只表示 PO-101；totalPaid 汇总全部 PO 的累计供应商付款。默认预置模式初始设置未经时间锁；空模式五参数/部署资金全零，暂停且无登记/授权，完整配置走时间锁。PO-101 只允许一次性，其他 PO 可配置周期。
- 任意 PO 可立即降额或延迟 120 秒提额，保留已付历史。降额和关闭取消该 PO 的待执行提额；关闭后不可调额。一次性以累计已付、周期以本周期已付为降额底线；调额不延期、不重启周期、不增加资金。PO-101 新旧入口共用同一待执行记录。
- 已授权 Agent 的规则拒付记录 Blocked，未授权调用回滚；交易成功不等于付款成功，必须解析 Paid/Blocked。原拒付编码 0–10 保留，追加 VendorInactive、POVendorMismatch、POClosed。

操作见 [控制台功能指南](REGISTRY_TEST.md)，详细规则见 [设计记录](superpowers/specs/2026-10-07-registry-controls-design.md)，原方案差异见 [PDF 对应清单](PDF_ALIGNMENT.md)。
