# Countersign 第一版本地测试

本版本把提供的页面、Python 后端和本地 `CountersignDemo.sol` 接在一起。只连接本机 Anvil（chain ID 31337），没有公链交易、真实资金或公网发布。

## 在这台电脑启动

在 countersign 目录执行：

```bash
./local.sh start        # 原预置演示
# 或 ./local.sh start-empty：空部署，再经时间锁完整初始化
./local.sh status
./local.sh stop
```

打开 http://127.0.0.1:5173/ ，首页点「创建账户」或「登录」后进入工作台。启动脚本使用项目 `.venv`、`.tools/forge`、`.tools/anvil` 和已安装的前端依赖；Node 从 PATH 查找，在本机也可使用 Codex 提供的 Node。

四个服务只监听 `127.0.0.1`：页面 5173、后端 8000、认证 3000、模拟链 8545。不要用 `0.0.0.0`，不要开放端口、配置隧道或直接将本版本部署到服务器。新版后台 `/api/` 要求有效登录会话，登录后不再使用任意占位令牌进入本地工作台。浏览器不需要安装钱包。控制台仍需点击「本机测试账户（无真实签名）」；该连接选择 Anvil 的无价值解锁账户，管理操作通过本地后端发送，不能作为生产角色认证或真实签名证据。账户共用一个演示工作区，详见 [页面与登录指南](SITE_ACCESS.md)。

两种模式同模式运行时复用，另一模式运行时拒绝启动；要改模式，先自行执行 stop，脚本不会自动停链。每次停止后重新启动，会创建**全新的本地链和账本**，初始余额 500、PO-101 额度 500、每日限额 200；空模式另外配置供应商 8 和 PO-102（每 30 天 100）。这是新部署，不是旧状态迁移。旧数据仍保存在被 Git 忽略的 `.runtime/<运行编号>/`，不会与新链混用。浏览器刷新不会清空同次运行记录。启动时检测端口；已有其他程序占用时退出，不杀其他进程。

## 空金库初始化验收

`./test.sh init-demo` 演示零登记/零授权/零资金的暂停金库，经两轮时间锁后可付款；`./test.sh init-script-demo` 核验实际部署脚本、回执与 HTTP 路由，使用独立临时链。

`./local.sh start-empty` 初始化成功后才启动页面。两轮各 120 秒由本机 Anvil 模拟；新实例初始时钟回退 240 秒以匹配推进，后续页面管理操作仍完整等待新 120 秒。默认 start 初始预置权限未经时间锁。查询区别、配置和失败处理见 [完整初始化说明](INITIALIZATION.md)。2026-10-07 独立端口的空模式部署、后端与原页面点击验收见 [STATUS](STATUS.md)，未重置用户现有链。

## 建议按这个顺序试

1. 收件箱先选择「带防护」（原页面默认「两个都发」，会对同一账单产生一次付款、一次重复拒付），点「正常付款」：账单 LOCAL-001 付款 100，金库和预算从 500 变 400。
2. 选择「裸奔」，点「错误收款地址」：显示 `PayoutMismatch`，不付钱，余额仍是 400。
3. 点「重复 LOCAL-001 账单」：显示 `DuplicateInvoice`。两个 Agent 共用账单防重记录。
4. 点「超出总预算」或「超出每日限额」：显示相应拒付原因。
5. 控制台点击「暂停所有付款」；再次提交正常样例，先得到 `Paused`，不再支付。
6. 点击「恢复付款」：生成 120 秒等待记录。到期前「执行」不可用；到期后点击「执行」才恢复。也可先点「取消」验证取消后不能执行。
7. 查看账本，点击交易链接：打开本机的真实交易回执 JSON，包含事件及本次运行编号。

已付过的 LOCAL-001 恢复后仍会被防重规则拒付。需要新账单时，在「挑战」页切到文字输入，填写：

```json
{"invoice_number":"MY-002","amount":"25"}
```

默认供应商 7、采购单 101、当前登记收款地址。可显式输入 `vendor_id`、`po_id`、`pay_to` 测试错误字段。金额必须用字符串，最多 18 位小数；后端到合约的金额不用浮点数。账单标识按供应商编号、账单号、金额统一生成，与 Agent 身份无关。

## 四个页面的范围

- 收件箱：本地样例、上传、处理记录、付款提案、实际回执。
- 挑战：本机文字/文件提交入口，没有奖金或公开活动。
- 控制台：真实查询余额、预算、权限；支持暂停、延迟恢复、改收款地址、立即降额、延迟提额、Agent 撤销及延迟授权、供应商新增/停用、采购单新增/关闭、延迟提款、执行/取消。
- 账本：读取当前合约实际事件，区别付款、规则拒付和治理事件。

供应商新增/停用、采购单新增/关闭、周期预算和延迟提款的操作见 [REGISTRY_TEST.md](REGISTRY_TEST.md)。每个 PO 独立预算，共享每日上限和金库；旧 totalBudget/remainingBudget/totalSpent/poExpiry 仅表示 PO-101，totalPaid 才是全部 PO 的累计供应商付款。ERC-20、Owner 交接和公链交付仍未实现，完整 PDF 方案尚未全部完成。

**未连接真实 AI、OCR 或隐藏文本检测。** 样例和 JSON 使用明确标注的确定性测试规则；guarded 会先拒绝错误地址，naive 会把提案交给合约判定。文件可上传、保存并预览（PDF 显示第一页，图片最长边 1200 像素），但进入人工核对，不能从图片/PDF 自动付款。无模型评测成绩；不应把这些测试称作 AI 防攻击效果。

## 故障与恢复

- 端口占用：先确认是否是自己的旧实例，可用 `./local.sh status`；不要关闭不明程序。
- 启动失败：查看 `.runtime/<运行编号>/runtime.log`、`backend.log`、`frontend.log`。Anvil 原始启动输出已关闭，避免输出测试私钥。
- 后端异常中断：未完成记录标记错误，不自动重发付款；需核对本次账本。第一版没有生产级交易恢复机制。
- 本地链被外部重置：后端校验部署区块，不会继续把新链当旧链；停止后重新启动整套服务。
- 目录改名后仍看到旧页面或白屏：2026-10-07 已修复 status 对旧实例的识别，独立启动的新版页面正常；旧白屏的具体缓存/模块根因尚未定位。修代码不会替已运行服务加载全部新版；确认可另建测试链后再停止并启动，不能把重启当作旧账本迁移。

## 新电脑安装

完整下载、依赖安装、自己注册账户及 Owner 测试身份步骤见 [队友测试指南](TEAM_TEST.md)。Windows 使用 WSL2；每台电脑建立独立本地实例，不共享作者的账户、余额或账本。

需要 Python 3.11+、Node、pnpm，以及 Foundry 的 Forge/Anvil；本机验证使用 Python 3.12、Foundry 1.7.1、Solidity 0.8.30。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-local.lock
.venv/bin/python -m pip install --no-deps -e ./backend
cd frontend
pnpm install --frozen-lockfile --ignore-scripts
cd ..
```

将官方 Forge、Anvil 可执行文件放到 `.tools/`。Foundry 测试依赖安装方式见根目录 README。依赖安装可能联网，但运行测试版不需要公共 RPC、模型密钥、钱包私钥或真实代币。

## 开发验证

```bash
./test.sh
.venv/bin/python -m pytest -q backend/tests
cd frontend
pnpm run typecheck
pnpm run check:interface
pnpm run check:controls
pnpm run build
```

整合测试自行启动独立临时 Anvil 端口并关闭，不修改当前页面使用的测试链。检查范围是本地 HTTP、数据库、合约回执和余额；不代表安全审计、公链运行或真实浏览器钱包签名完成。

`check:controls` 直接检查页面发送入口与等待行：断开、错链和非 Owner 管理操作不发送，已连接账户仍可执行到期申请，按钮到期状态以后台为准而非本机时钟。它不发交易，不能替代浏览器联调。

父目录改名后，`status/stop/start` 按 Python 管理进程的脚本、`serve` 和完整运行编号识别同次实例，不再要求旧进程路径等于当前绝对路径。修代码不会自动重启已运行实例；停止再启动仍创建新测试链与账本，旧记录保留在 `.runtime/`。
